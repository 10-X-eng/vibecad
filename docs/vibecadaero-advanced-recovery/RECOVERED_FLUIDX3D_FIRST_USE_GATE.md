# Recovered FluidX3D first-use acknowledgment gate

Recovered 2026-08-25 from the signed-in ChatGPT Library associated with the VibeCAD work. This file corrects the earlier recovery that incorrectly left the backend unresolved.

## Confirmed identity

The backend attached to the remembered **I understand** checkbox is **FluidX3D**. It is not EIRENE.

The two original source documents are:

- `AERO_FIRST_USE_INFORMATIONAL_NOTICE.md`, August 19, 2.19 KB;
- `CORRECTION_01_FLUIDX3D_VENDOR_POLICY.md`, August 19, 1.53 KB.

## Exact first-use behavior

The recovered source requires VibeCADAero to:

1. Show the notice once, the first time the user enters VibeCADAero.
2. Present an acknowledgment labeled **I understand.** followed by **Continue**.
3. Persist one local, unversioned boolean after the user checks **I understand**.
4. Never show the notice again during normal use or after updates.
5. Keep the flag local and non-telemetric.
6. Give the flag no effect on solver eligibility, licensing, product behavior, or output ownership.

## Recommended notice copy recovered from the original plan

> **Third-Party Software Notice**
>
> VibeCAD Aero can use third-party software with license terms separate from VibeCAD. FluidX3D is one such solver. FluidX3D's current license places restrictions and conditions on use of FluidX3D, including commercial and military use. Those terms apply to FluidX3D within the scope of its own license; they do not make VibeCAD or VibeCADAero non-commercial, do not apply to unrelated Aero backends or features, and do not change ownership of CAD designs created in VibeCAD.
>
> Please review Third-Party Notices for the authoritative component-specific terms.
>
> **I understand.**
>
> **Continue**

## Explicit non-meanings

The original plan is unusually clear that this acknowledgment is not:

- an **I agree** license acceptance;
- a declaration of intended use;
- a commercial, military, or research classification;
- an entitlement or compliance check;
- a restriction on VibeCAD or VibeCADAero generally;
- a restriction on ownership of user-created CAD designs;
- a solver-selection control;
- a recurring prompt.

This is therefore a one-time informational acknowledgment, not a policy-enforcement or authorization system.

## FluidX3D commercial-use note

The recovered plan records that FluidX3D's then-current public license did not publish a standard commercial agreement. Commercial use required explicit permission from the copyright owner. The official README said a second commercial license might be offered in the future and invited interested users to contact the author. At the reconciliation point, no standard price, EULA, redistribution grant, or required deployment model was published.

The plan also required documentation of FluidX3D's altered-source publication condition: when data or results generated by an altered FluidX3D source version are published, the altered source code must also be published under the reviewed FluidX3D terms. This is a FluidX3D-specific condition and does not relicense the CAD design itself.

## Recovered vendor and packaging policy

The separate correction document superseded earlier statements describing FluidX3D as always external, never vendored, or separately installed without regard to distribution profile.

The corrected canonical rule is:

1. **Non-commercial distribution:** vendor a pinned FluidX3D source at `src/Mod/VibeCADAero/vendor/FluidX3D/`; preserve upstream license and origin; build the VibeCAD bridge against it; package the bridge with the product.
2. **Commercial distribution:** exclude or disable the vendored payload by default; require a separately installed FluidX3D backend covered by compatible commercial permission, unless the project later obtains permission allowing commercial bundling.
3. **Military-use restriction:** keep it independent; under the reviewed terms, military use is prohibited unless separately permitted by the copyright holder.
4. **No runtime auto-download:** vendoring occurs during source/release engineering, not through a first-run network installer.
5. **Stable solver abstraction:** keep AeroLBM behind the solver interface so distribution and licensing policy can change without contaminating the CFD case/result contract.

## Implementation boundary

This recovery establishes the historical design contract. It does not claim that the current VibeCAD repository already implements the notice, local flag, distribution profiles, or vendor boundary. Those require a separate current-tree implementation audit.
